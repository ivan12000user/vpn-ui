## Что входит в исходники

| Путь | Содержимое |
| --- | --- |
| `src/` | Rust UI/API, включая `tailscale.rs`, настройки и AWG 3.1 |
| `Cargo.toml`, `Cargo.lock` | Версия пакета, требования Rust и фиксированные зависимости |
| `deploy/bin/`, `deploy/libexec/` | Обёртки, управление пирами, генераторы профилей |
| `deploy/sudoers/` | Ограниченные правила доступа к помощникам |
| `deploy/systemd/` | Движок AWG 3.1 и отдельные drop-ins UI |
| `deploy/nginx/` | Пример конфигурации frontend |
| `tests/` | Offline-проверки помощников, staging и HTTP smoke |
| `.github/workflows/` | Проверки кандидата, сборка для WSL и аудит внешнего AWG |

Это исходники приложения и его помощников, но ещё не полный установщик чистого
VPS. Не хватает переносимого описания базового vpn-ui unit, пользователя,
настроек конкретного хоста и проверенного полного install/rollback rehearsal.
Подробности: [RELEASE_READINESS.md](../deploy/RELEASE_READINESS.md).

Движок `amneziawg-go` — отдельный upstream-проект. Его исходники, Go toolchain
и лицензия описаны в release gates. Совпадение исходной версии upstream не
доказывает происхождение установленного бинарника; замена движка не входит
в упорядочивание UI.

## Исходники, сборки и runtime — разные вещи

- Git checkout содержит исходники и историю.
- `target/release/vpn-ui` — результат сборки; `target/` не коммитится.
- Каталог `/home/user/vpn-ui-v080-lab` на Z270 содержит работающий бинарник,
  но не является Git checkout. Его нельзя использовать как исходную базу.
- На VPS `/root/src/vpn-ui` обнаружен старый checkout `aa888ad`, тогда как
  работающий UI уже показывает AWG 3.1 и Tailscale. Этот checkout не является
  доказательством происхождения работающего бинарника.
- Приватные ключи, клиентские конфиги, инвентарь, пароли и резервные копии
  остаются runtime-данными сервера; в Git их не переносить.

Cargo version пока `0.7.0` и у кандидата. Название каталога `v080` и надпись
версии в UI не определяют commit. Для каждой новой сборки сохранять
SOURCE_COMMIT, BUILD_PLATFORM и SHA256SUMS рядом с бинарником.
Не присваивать старому бинарнику предполагаемый commit задним числом.

поставляемых systemd-файлов совпали с кандидатом `8735531`.
Это подтверждает совпадение этих файлов, но не всего хоста или Rust бинарника.

Следующее изменение production должно исходить из конкретного diff и иметь
проверенный откат. Сборка и документирование не требуют перезапуска VPN.
